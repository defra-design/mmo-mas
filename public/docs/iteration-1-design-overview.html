Iteration 1 – design overview

Iteration 1 established the initial caseworker journey for receiving and assessing a marine licence application. The intended approach is for the caseworker to open a case and review the submitted application across the tabs, checking that everything is in order before beginning the assessment tasks.

Case list

The Case list provides the starting point for finding and opening a marine licence case. It brings together the reference, project name, assigned caseworker, status, case age in days and notifications.

Caseworkers can sort the list through the column headings and apply filters to narrow the results. The list remembers the last-used sort order. Status and assigned-caseworker filters allow selections from the values in the list.

The grid follows the Dynamics 365 presentation: single-line rows, truncated long text and horizontal scrolling where needed. Longer project names can be read by hovering over clipped text.

Case references provide access to the developed example cases. The list also includes illustrative records and controls that do not yet have a complete onward journey.

Review tabs

The review tabs display the information submitted by the applicant so the caseworker can check the application before beginning the assessment tasks. Applicant information is read-only.

  • Case summary

    Displays the reference, application type, submission date, fee band, applicant, organisation and case officer.

    The header shows the project name, reference, status, case age and assignment across the tabs. In Iteration 1, the Tasks panel remains visible on the right.

  • Project details

    Displays the applicant’s project name, project background and preferred licence start and end dates.

  • Sites and activities

    Displays the method used to provide the site location, site name and map view, followed by the activity type, what is being constructed, activity description, duration, timing restrictions and working hours.

  • Marine plan policies

    Displays policy information alongside the applicant’s consideration of each policy. Policies are grouped in a navigation list, with the selected policy’s details shown alongside it. Where no consideration has been provided, this is stated.

  • Water Framework Directive

    Displays the applicant’s answers about the project’s location in relation to the WFD assessment area, whether it is limited to an excluded activity, and any assessment document provided.

    In the application journey, applicants do not need to carry out or provide a WFD assessment if they answer that the site is outside the WFD assessment area, or that it is within the area but the activity is excluded. The area includes sites within one nautical mile of the coast, or in a tidal river or estuary.

  • Other permissions

    Displays the applicant’s information about special legal powers, the harbour authority, other authorities and pre-application consultation. The caseworker selects a topic to read its details.

  • Public register

    Displays the applicant’s response to “Consent to publish your project information”.

Tasks

  • Site check

    After reviewing the application, the caseworker can open the Site check task from the Tasks panel.

    The intention is that Site check must be completed before any of the other tasks become available. This is to identify problems early, such as a site being outside MMO jurisdiction, coordinates that do not accurately represent the location of the works, or a site whose location, shape or size is inappropriate for the proposed activity.

    The task asks the caseworker to check that the coordinates accurately represent the location of the works, that the shape and size are appropriate for the activity, and that the site is within MMO jurisdiction.

    Case Officers carry out their location checks in another system called SPIRIT. The Download CSV link represents a download of the site coordinates for upload to SPIRIT, intended to replace the several manual steps currently needed to prepare the coordinates.

    The task also asks whether the site is within the WFD assessment area. As Case Officers are already checking the location in SPIRIT, Iteration 1 explores whether it makes sense to answer this question during Site check. The intention is to play this answer back in the WFD task.

    Caseworkers can also enter notes relevant to later stages of the assessment.

    Selecting Save task returns the caseworker to the Case summary, marks Site check as Done, and changes the WFD and Marine plan policies task statuses from Cannot start yet to To do.

  • Water Framework Directive

    The WFD task becomes available after Site check has been completed.

    It brings the applicant’s key WFD answers and any assessment document provided into the task form. Applicants do not need to carry out or provide an assessment if they answer that the site is outside the WFD assessment area, or that it is within the area but the activity is excluded. The area includes sites within one nautical mile of the coast, or in a tidal river or estuary.

    The task also shows the WFD location confirmation from Site check, labelled “Confirmed in Site check”. This explores playing back the Case Officer’s earlier location check alongside the applicant’s answers. In the Iteration 1 example, this confirmation is illustrative rather than dynamically linked to the saved Site check answer.

    The caseworker then answers: “Is the WFD section complete and acceptable?”

    The caseworker records a Yes or No answer. Selecting Save task marks the task as Done and returns them to the Case summary.

    In this iteration, Done indicates that the review task has been completed; it does not itself mean that the caseworker answered Yes.

  • Marine plan policies

    Marine plan policies appears in the Iteration 1 task list to show its place in the assessment sequence.

    It initially displays Cannot start yet, changing to To do after Site check is saved. At this stage, it is a task-list placeholder: the applicant’s policy responses can be reviewed in the tab, but the assessment task itself is not implemented.

Saving and returning to work

Iteration 1 retains task answers and statuses in the browser so they remain available after refreshing the page. Task forms also display a Saved or Unsaved indicator.

A reset option supports returning the prototype to its initial state for another walkthrough or testing session.

This is a prototype using example application data and browser storage. The draft describes the supported review and task journey, rather than implying that every visible command or external-system connection is functional.
